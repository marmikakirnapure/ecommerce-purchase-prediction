# GitHub, Deployment and Cross-Platform Checklist

The project code is prepared for GitHub and Streamlit Community Cloud. Publishing requires signing in to your own GitHub/Streamlit accounts, so this ZIP does not claim that a public repository or public URL already exists.

## A. Upload to GitHub

1. Sign in at https://github.com and create a **new public repository** named `ecommerce-purchase-prediction`.
2. Do not add a README on GitHub if you are uploading this project's existing README.
3. Extract this ZIP and open the `ecommerce_purchase_prediction_project` folder in VS Code.
4. Open **Terminal → New Terminal** and run these commands from that folder:

```bash
git init
git add .
git commit -m "Add ecommerce purchase prediction project"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/ecommerce-purchase-prediction.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your GitHub username. If Git asks you to sign in, complete GitHub's authentication flow. If you already initialized a repository or added a remote, do not repeat those commands blindly; check with `git status` and `git remote -v` first.

## B. Deploy the Streamlit website

1. Sign in at https://share.streamlit.io using your GitHub account.
2. Choose **Create app** and select the repository you just uploaded.
3. Select branch `main` and main file path `app.py`.
4. Deploy. Keep `requirements.txt`, `app.py`, `train.py`, `data/`, `models/`, and `outputs/` in the repository.
5. Open the generated public URL and test predictions and model comparison.
6. Add that real URL to the final report. Do not put a made-up URL in your submission.

Official instructions: https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app

## C. Desktop and mobile testing

- Open the deployed URL on a laptop/desktop browser.
- Open the same URL on a phone browser (or use browser developer tools to emulate a phone).
- Confirm tabs, form fields, prediction results, tables and graphs are readable and usable.
- Make a prediction on both screen sizes and record screenshots for the report.
- If a screen element is clipped or too wide, fix it and redeploy before submission.

## D. Marks checklist

- [ ] Data cleaning and 80:20 stratified split are shown in `train.py`.
- [ ] Four models, 3-fold stratified CV, grid search, metrics and plots are generated by `train.py`.
- [ ] Streamlit UI starts locally with `streamlit run app.py`.
- [ ] GitHub repository is pushed and accessible to the evaluator.
- [ ] Streamlit public URL works and has been tested on desktop and mobile.
- [ ] Report includes actual metrics, screenshots, repository URL, deployed URL, references and limitations.
